# 02 Tool Calling Rules / 工具调用规则

本文件定义 Agent 在什么情况下调用产品检索能力，什么情况下进入产品维护流程。

## 一、默认：产品查询

以下场景默认调用 05 Retrieval Tool：

- 推荐产品
- 查某个 SKU
- 查价格 / MOQ / 工厂 / 材质 / 尺码
- 查适用场景
- 比较多个产品
- 根据客户需求找合适产品

例如：

```text
“推荐几个户外鞋垫”
“F0228 的 MOQ 是多少”
“有没有 PU、MOQ 3000 以内的鞋垫”
```

均属于查询，不进入 03。

---

## 二、明确维护意图才进入 03

只有同时满足以下特征时，才进入产品维护流程：

1. 用户明确提供产品资料，例如表格、图片、SKU、工厂、价格、MOQ 等；
2. 用户明确表达新增、修改、替换、删除等维护意图。

例如：

```text
“把这个新产品表格导入产品库”
“F0228 富置高的价格改成 7.2”
“把这个 SKU 的主图替换掉”
“新增一个王氏的 Factory Offer”
```

处理链路：

```text
明确维护请求
→ 03 Data Management
→ 候选变更
→ 人工确认
→ ⑤ Data Validation
→ PASS
→ 写入 Product_KB
```

---

## 三、不要把普通信息误判成更新

用户在聊天里提到：

```text
“F0228 好像是 6.9”
“客户说 MOQ 可能要 3000”
```

如果没有明确要求修改 Product_KB：

```text
→ 不更新
→ 仍视为普通对话上下文
```

---

## 四、缺少关键条件时

查询时如果条件不完整：

- 可以先返回已有匹配结果；
- 只有缺失条件会明显影响检索正确性时，再补问。

不要为了形式完整而过度追问。
