# 06 索引存储与运行方式

本文件定义真实检索索引如何存放，以及不同智能体平台如何按同一规则建立自己的运行索引。

核心原则：

> GitHub 保存规则和代码；产品知识库是真实资产；向量索引属于平台运行时派生数据，可以重建。

---

## 一、推荐目录

```text
Product_Data/
├─ Product_KB/
│  └─ 真实产品资料
│
└─ Search_Index/
   ├─ records/
   ├─ keywords/
   ├─ vectors/
   └─ index_meta/
```

### records

保存结构化产品检索记录。

### keywords

保存自动提炼的关键词及对应关系。

### vectors

保存当前运行平台生成的产品向量和对应关系。

### index_meta

至少保存：

```text
索引版本
向量模型名称
向量模型版本
向量维度
相似度算法
语义文本规则版本
生成时间
索引状态
```

---

## 二、GitHub 保存什么

GitHub 只保存：

- 字段定义
- 语义文本生成规则
- 关键词生成规则
- 向量能力要求
- 建库完整自检规则
- 查询轻量兼容检查规则
- 混合检索规则
- 排序规则
- 平台适配说明

GitHub 不保存：

- 真实产品数据
- 产品图片
- 工厂报价
- 产品语义文本索引
- 产品关键词索引
- 产品向量
- 客户信息

---

## 三、不同平台可以有不同向量索引

不要求：

```text
Accio 向量
=
WorkBuddy 向量
```

允许：

```text
同一 Product_KB
↓
Accio 按规范建立自己的向量索引

同一 Product_KB
↓
WorkBuddy 按规范重新建立自己的向量索引
```

真正跨平台保持一致的是：

- Product_KB
- 语义文本生成规则
- 检索规则
- 自检标准
- 排序规则

向量本身不是必须跨平台保存的核心资产。

---

## 四、平台需要提供的最低向量能力

平台如果要启用语义向量检索，至少要能：

```text
文本 → 向量
向量 → 相似度比较
新增向量
更新向量
删除向量
按查询向量召回相似候选
```

并且能够识别或记录当前：

- 向量模型
- 模型版本
- 向量维度

不强制使用某个固定厂商、模型或 API。

---

## 五、建库 / 更新阶段

首次建立或重大更新时：

```text
检查 Product_KB
↓
按固定规则生成语义文本
↓
确认当前向量模型环境
↓
生成向量
↓
完成完整自检
↓
跑固定测试集
↓
通过后标记索引为“正常”
```

如果模型或语义规则变化：

```text
旧索引标记不兼容
↓
重建向量
↓
重新验收
```

---

## 六、日常查询阶段

产品索引已经验收通过后，日常查询只做轻量检查：

```text
当前查询向量模型/版本
是否与索引一致
↓
维度是否一致
↓
索引状态是否正常
↓
通过 → 直接查询
```

不重复执行完整测试集。

聊天大模型是谁不影响这里的兼容性。

---

## 七、索引状态

建议保持简单：

```text
正常
待更新
重建中
向量缺失
不兼容
异常
```

如果向量缺失或异常：

- 结构化检索仍可工作；
- 关键词检索仍可工作；
- 向量检索临时停用；
- 后续补建或重建。

---

## 八、前期不强制大型向量数据库

对于几百到一千左右 SKU：

- 不需要为了规模提前部署重型向量数据库；
- 可以使用平台自带的向量能力；
- 也可以使用轻量索引；
- 重点是满足 04⑤ 的一致性和验收要求。

平台变化时可以重新建索引，不必强求旧向量文件继续复用。

---

## 九、运行平台与核心资产解耦

推荐关系：

```text
Product_KB
+
GitHub 检索规则
↓
某个平台运行时
↓
生成该平台自己的检索索引
↓
提供给业务员查询
```

因此：

```text
换 Accio / WorkBuddy / 其他平台
→ 核心产品资料不变
→ 规则不变
→ 重新生成该平台索引即可
```

---

## 十、数据备份原则

最重要的备份对象：

```text
Product_KB
```

因为：

```text
Search_Index
= 可重建派生数据
```

真正不能丢的是：

- 标准化产品资料
- 产品图片
- 工厂报价
- 已人工确认的信息

---

## 十一、核心原则

1. 产品知识库是真源。
2. GitHub 保存方法，不保存真实业务索引。
3. 向量索引属于平台运行时派生数据。
4. 不绑定固定厂商、固定向量 API 或固定聊天大模型。
5. 同一索引内部必须保持向量模型一致。
6. 建库 / 更新时完整自检。
7. 日常查询时只做轻量兼容检查。
8. 换平台时允许重新生成整套向量索引。
9. 向量能力异常时，结构化 + 关键词检索仍可继续运行。
