# 06 索引存储与运行方式

本文件定义真实检索索引如何存放，以及任意智能体平台如何按同一规则建立自己的运行索引。

核心原则：

> GitHub 保存规则和代码；产品知识库是真实资产；V1 使用统一的向量模型，但各平台可以重新生成自己的运行索引。

---

## 一、推荐目录

```text
Product_Data/
├─ Product_KB/
│  └─ 真实产品资料
│
└─ Search_Index/
   ├─ records/
   ├─ keywords/
   ├─ vectors/
   └─ index_meta/
```

### records

保存结构化产品检索记录。

### keywords

保存自动提炼的关键词及对应关系。

### vectors

保存当前运行平台生成的产品向量和对应关系。

### index_meta

至少保存：

```text
索引版本
向量模型名称
向量模型版本
向量维度
相似度算法
语义文本规则版本
生成时间
索引状态
```

---

## 二、V1 统一运行模型

当前 V1 固定：

```text
Embedding Model:
intfloat/multilingual-e5-small

Dimension:
384
```

任意智能体平台接入本 Skill 时：

- 可以在自己的运行环境中下载和加载该模型；
- 可以生成自己的本地索引文件；
- 但不得自行换成其他模型继续写入同一索引。

未来如需升级模型，必须人工确认并整库重建。

---

## 三、GitHub 保存什么

GitHub 保存：

- 字段定义
- 语义文本生成规则
- 关键词生成规则
- V1 向量模型名称和运行要求
- 建库完整自检规则
- 查询轻量兼容检查规则
- 混合检索规则
- 排序规则
- 平台适配说明

GitHub 不保存：

- 真实产品数据
- 产品图片
- 工厂报价
- 产品语义文本索引
- 产品关键词索引
- 产品向量
- 模型权重文件
- 客户信息

---

## 四、不同平台可以重建自己的索引

不要求不同智能体平台共享同一个向量索引文件。

允许：

```text
同一 Product_KB
+
同一个 multilingual-e5-small
↓
平台A 建立自己的索引

同一 Product_KB
+
同一个 multilingual-e5-small
↓
平台B 重新建立自己的索引
```

真正跨平台保持一致的是：

- Product_KB
- V1 向量模型
- 语义文本生成规则
- 检索规则
- 自检标准
- 排序规则

索引文件本身属于可重建派生数据。

---

## 五、平台需要提供的最低运行能力

任意平台如果要启用本地语义向量检索，至少要能：

```text
运行 Python / Node
读取 Product_KB
加载 multilingual-e5-small
文本 → 384维向量
保存和读取本地索引
新增 / 更新 / 删除向量记录
按查询向量召回相似候选
把检索结果返回给上层 Agent
```

平台不需要自己提供 Embedding API。

---

## 六、建库 / 更新阶段

首次建立或重大更新时：

```text
检查 Product_KB
↓
按固定规则生成语义文本
↓
检查 multilingual-e5-small 运行环境
↓
生成产品向量
↓
写入本地向量索引
↓
完成完整自检
↓
跑固定测试集
↓
通过后标记索引为“正常”
```

---

## 七、日常查询阶段

产品索引已经验收通过后：

```text
检查当前查询模型仍为 multilingual-e5-small
↓
检查模型版本一致
↓
检查维度 = 384
↓
检查索引状态正常
↓
生成查询向量
↓
执行混合检索
```

不重复执行完整测试集。

聊天大模型是谁不影响这里的兼容性。

---

## 八、索引状态

建议保持：

```text
正常
待更新
重建中
向量缺失
不兼容
异常
```

如果向量缺失或异常：

- 结构化检索仍可工作；
- 关键词检索仍可工作；
- 向量检索临时停用；
- 后续补建或重建。

---

## 九、当前规模不需要重型向量数据库

对于当前 ≤1000 SKU 的规模：

- 不部署大型向量数据库；
- 优先使用轻量本地向量索引；
- 当前可使用 FAISS 这一类轻量方案；
- 重点是保证模型一致、索引可更新、结果可验证。

以后产品规模明显增长时，再评估是否升级底层索引实现。

---

## 十、运行平台与核心资产解耦

推荐关系：

```text
Product_KB
+
GitHub 检索规则
+
multilingual-e5-small 模型规定
↓
任意智能体平台运行时
↓
生成该平台自己的检索索引
↓
提供给业务员查询
```

因此：

```text
更换任意智能体平台
→ Product_KB 不变
→ 检索规则不变
→ V1 向量模型不变
→ 在新平台重新生成索引即可
```

---

## 十一、数据备份原则

最重要的备份对象：

```text
Product_KB
```

因为：

```text
Search_Index
= 可重建派生数据
```

真正不能丢的是：

- 标准化产品资料
- 产品图片
- 工厂报价
- 已人工确认的信息

---

## 十二、核心原则

1. 产品知识库是真源。
2. GitHub 保存方法和 V1 模型规定，不保存真实业务索引。
3. V1 固定使用 intfloat/multilingual-e5-small。
4. 向量索引属于平台运行时派生数据。
5. 不绑定固定聊天大模型或固定智能体平台。
6. 同一索引内部必须保持模型、版本、维度一致。
7. 建库 / 更新时完整自检。
8. 日常查询时只做轻量兼容检查。
9. 更换平台时允许重新生成整套向量索引。
10. 更换向量模型必须人工确认并整库重建。
11. 向量能力异常时，结构化 + 关键词检索仍可继续运行。
