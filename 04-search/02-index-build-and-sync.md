# 02 索引建立与变更同步

本文件定义产品知识库如何自动生成检索索引，以及产品发生变化后哪些索引需要同步更新。

核心原则：

> 产品资料只维护一份；关键词、语义文本和向量都由系统自动派生。

---

## 一、首次建立索引

首次运行：

```text
产品知识库
↓
读取每个 product.md
↓
按 04① 生成“产品货号 + 工厂报价”检索记录
↓
自动提炼关键词
↓
自动生成语义检索文本
↓
生成语义向量
↓
分别写入
├─ 结构化索引
├─ 关键词索引
└─ 向量索引
```

业务人员不需要逐款手工编写关键词、语义文本或向量。

---

## 二、索引分成三类

### 1. 结构化索引

用于精确筛选：

- 产品品类
- 产品货号
- 工厂
- 材质
- 价格
- 起订量
- 尺码
- 功能标签
- 场景标签
- 特殊属性
- 性能属性

### 2. 关键词索引

用于明确词语命中：

- 标准功能词
- 场景词
- 材质词
- 特征词
- 标准同义词

### 3. 向量索引

用于：

- 模糊自然语言
- 不完全使用标准词的表达
- 相似产品
- 使用场景描述
- “想要这种感觉”的需求

---

## 三、接收 03 的变更通知

03 数据管理告诉 04：

> 哪个产品货号 / 哪个工厂报价发生了什么变化。

04 负责判断：

> 需要更新哪一类索引。

---

## 四、增量同步规则

### 新增产品

```text
→ 为该产品所有工厂报价建立检索记录
→ 提炼关键词
→ 生成语义文本
→ 生成向量
→ 写入全部索引
```

### 新增工厂报价

```text
→ 新增对应检索记录
→ 继承产品层关键词和语义信息
→ 写入结构化索引
→ 如工厂材质差异会改变语义，则重新生成该记录语义文本与向量
```

### 修改价格 / 起订量

```text
→ 只更新结构化索引
→ 不重新生成向量
```

### 修改尺码

```text
→ 更新结构化索引
→ 一般不重新生成向量
```

### 修改主材质 / 详细材质

```text
→ 更新结构化索引
→ 更新关键词
→ 重新生成语义文本
→ 重新生成向量
```

### 修改功能 / 场景 / 特殊属性 / 性能

```text
→ 更新结构化索引
→ 更新关键词
→ 重新生成语义文本
→ 重新生成向量
```

### 修改图片

```text
→ 更新图片引用
→ 不重新生成关键词
→ 不重新生成向量
```

### 删除工厂报价

```text
→ 删除对应检索记录
→ 删除该记录的结构化 / 关键词 / 向量索引
```

### 删除产品

```text
→ 删除该产品全部工厂检索记录
→ 删除相关全部索引
```

---

## 五、什么时候重新生成向量

只有“产品语义发生变化”时才重建向量。

需要重建的典型字段：

- 主材质
- 详细材质
- 功能标签
- 场景标签
- 特殊属性
- 性能属性
- 未来增加的核心使用特征

通常不需要重建：

- 价格
- 起订量
- 图片
- 内部备注
- 不影响产品语义的管理字段

---

## 六、索引版本

每条检索记录应保留：

```text
记录版本
语义文本版本
向量模型版本
最后更新时间
```

用途：

- 判断旧向量是否需要批量重建；
- 以后更换向量模型时能够全量更新；
- 避免产品资料已更新但索引仍然使用旧数据。

---

## 七、异常处理

如果关键词生成成功但向量生成失败：

```text
结构化索引 + 关键词索引仍可使用
向量状态标记为待补充
```

不能因为向量失败导致整套产品检索不可用。

---

## 八、核心原则

1. 产品知识库是唯一真实产品数据源。
2. 所有索引都可以从产品知识库重建。
3. 增量更新优先，不因小变化全量重建。
4. 精确字段变化与语义字段变化分开处理。
5. 向量是增强能力，失败时不能破坏基础检索。
6. 真实索引数据不进入 GitHub。
