# 02 索引建立与变更同步

本文件定义产品知识库如何自动生成检索索引，以及产品发生变化后哪些索引需要同步更新。

核心原则：

> 产品资料只维护一份；关键词、语义文本和向量都由系统自动派生。

---

## 一、首次建立索引

首次运行：

```text
产品知识库
↓
读取每个 product.md
↓
按 04① 生成“产品货号 + 工厂报价”检索记录
↓
自动提炼关键词
↓
自动生成语义检索文本
↓
确认当前向量模型环境
↓
生成语义向量
↓
分别写入
├─ 结构化索引
├─ 关键词索引
└─ 向量索引
↓
完整自检
↓
固定测试集验收
↓
索引状态 = 正常
```

业务人员不需要逐款手工编写关键词、语义文本或向量。

---

## 二、索引分成三类

### 1. 结构化索引

用于精确筛选：

- 产品品类
- 产品货号
- 工厂
- 材质
- 价格
- 起订量
- 尺码
- 功能标签
- 场景标签
- 特殊属性
- 性能属性

### 2. 关键词索引

用于明确词语命中：

- 标准功能词
- 场景词
- 材质词
- 特征词
- 标准同义词

### 3. 向量索引

用于：

- 模糊自然语言
- 不完全使用标准词的表达
- 相似产品
- 使用场景描述
- 感受型需求

---

## 三、接收 03 的变更通知

03 数据管理告诉 04：

> 哪个产品货号 / 哪个工厂报价发生了什么变化。

04 负责判断：

> 需要更新哪一类索引。

---

## 四、增量同步规则

### 新增产品

```text
→ 建立检索记录
→ 提炼关键词
→ 生成语义文本
→ 使用当前索引对应的向量模型生成向量
→ 写入全部索引
→ 做该记录的必要校验
```

### 新增工厂报价

```text
→ 新增对应检索记录
→ 继承产品层关键词和语义信息
→ 如工厂材质差异改变语义，则重新生成该记录语义文本与向量
```

### 修改价格 / 起订量

```text
→ 只更新结构化索引
→ 不重新生成向量
```

### 修改尺码

```text
→ 更新结构化索引
→ 一般不重新生成向量
```

### 修改主材质 / 详细材质

```text
→ 更新结构化索引
→ 更新关键词
→ 重新生成语义文本
→ 重新生成对应向量
```

### 修改功能 / 场景 / 特殊属性 / 性能

```text
→ 更新结构化索引
→ 更新关键词
→ 重新生成语义文本
→ 重新生成对应向量
```

### 修改图片

```text
→ 更新图片引用
→ 不重新生成关键词
→ 不重新生成向量
```

### 删除工厂报价

```text
→ 删除对应结构化 / 关键词 / 向量记录
```

### 删除产品

```text
→ 删除该产品全部工厂检索记录及相关索引
```

---

## 五、什么时候需要整库重建向量

以下情况必须整库重建：

- 更换向量模型
- 更换向量模型版本且语义空间不兼容
- 向量维度发生变化
- 语义文本规则发生重大变化
- 索引出现大面积不一致或损坏

普通价格、起订量、图片变化不触发整库重建。

---

## 六、完整自检触发条件

完整自检主要发生在：

- 首次建库
- 大批量导入
- 整库重建
- 更换向量模型
- 更换语义文本规则

完整自检内容由 04⑤ 定义。

日常业务查询不重复执行完整自检。

---

## 七、日常查询只做兼容检查

查询阶段只需要确认：

```text
查询向量模型/版本
=
当前产品向量索引模型/版本
```

并确认：

- 向量维度一致
- 索引状态正常

通过后直接进入混合检索。

---

## 八、索引版本

每套索引至少记录：

```text
记录版本
语义文本规则版本
向量模型名称
向量模型版本
向量维度
索引版本
最后更新时间
```

用于判断是否需要增量更新或整库重建。

---

## 九、异常处理

如果向量生成失败：

```text
结构化索引 + 关键词索引仍可使用
向量状态标记为待补充
```

不能因为向量失败导致整套产品检索不可用。

---

## 十、核心原则

1. 产品知识库是唯一真实产品数据源。
2. 所有索引都可以从产品知识库重建。
3. 增量更新优先，不因小变化全量重建。
4. 精确字段变化与语义字段变化分开处理。
5. 向量模型变更属于索引级重大变化。
6. 建库 / 更新时完整自检，查询时轻量检查。
7. 向量是增强能力，失败时不能破坏基础检索。
8. 真实索引数据不进入 GitHub。
